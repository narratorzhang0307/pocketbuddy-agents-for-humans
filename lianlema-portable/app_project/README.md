# 练了吗 (Lian Le Ma)

> 你今天练了吗？

一个 **AI 健身教练**项目。仓库当前包含两套相互配合的子系统：

1. **应用层（AI 健身教练 App）** —— `backend/`（FastAPI）+ `app/`（React Native + Expo）：负责评估、计划、训练界面、动作纠错的呈现与情绪价值。
2. **模型层（姿态识别 / 动作分类与打分）** —— 仓库根目录的 `src/`、`model/`、`PoseTracking.py`、`web_app.py` 等：基于 RTMPose 姿态识别 + ST-GCN 时空图卷积，对动作做分类与打分，是动作纠错能力的模型来源。

两层通过稳定契约对接：App 端的动作分析走可替换的 `Form_Analysis_Provider`，模型就绪后由模型服务提供分析结果，App 端无需改动调用方。

---

## 一、应用层：AI 健身教练 App

完整的用户旅程：

- **运动评估**：采集训练目标、场地、可用器械、每周频率与伤痛风险自评（敏感健康信息需单独同意）。
- **7 天计划**：基于评估由确定性逻辑生成尊重场地/器械/频率/伤痛情况的训练计划。
- **摄像头动作纠错**：通过稳定契约消费动作识别模型的结构化分析结果，转换为面向用户的自然语言纠正建议（模型未就绪期间由桩实现占位，应用层不做生物力学判定）。
- **语音命令**：训练中以固定意图（暂停/继续/换动作/降低难度/再说一遍/结束）控制训练。
- **训练报告**：训练结束生成动作分、风险提示、纠正次数与下一次训练重点。
- **会员付费**：免费次数用尽后展示付费墙，经 Apple IAP 解锁 Pro 权益。
- **隐私授权**：摄像头、麦克风、HealthKit 分项授权，敏感健康信息单独明示同意。

> 设计红线：训练计划、动作分等数值由确定性纯函数产出，绝不由 LLM 生成；LLM 仅用于自然语言文案的生成或润色，且始终有模板兜底。动作"是否标准"的判定由模型层负责。

### 应用层目录

| 目录 | 说明 |
|------|------|
| `backend/` | FastAPI + Python 后端：业务编排、确定性计算、数据持久化与第三方能力调度。 |
| `app/` | React Native + Expo 移动客户端：评估问卷、训练界面、摄像头与语音采集、音频播放、付费墙与授权管理。 |

详细的需求、设计与实现计划见 `.kiro/specs/fitness-coach-agent/`。

## 二、模型层：基于人体姿态关键点的视频分类与打分

整合 **RTMPose 姿态识别**与 **ST-GCN 时空图卷积**两个模型，结合**距离角度判定算法**，实现"基于人体姿态关键点的视频分类和打分任务"。

- 源代码：`src/`（模型、训练、推理、打分、实时教练等）
- 预训练模型：`model/`
- 入口/演示：`PoseTracking.py`、`web_app.py`、`templates/`
- 训练数据（关键点 `.npy`）：`data/`、`config/`
- 设计与说明文档：`doc/`、`docs/`

模型层的完整训练流程、数据集构建、混淆矩阵与部署说明，详见 `doc/` 目录及各设计文档（`docs/superpowers/`）。模型层独立于应用层运行，依赖 PyTorch / ONNX Runtime，安装方式见 `requirements.txt`。

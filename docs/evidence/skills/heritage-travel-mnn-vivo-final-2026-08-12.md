## 古籍识读：三步真实链路

### 01 三路离线中文 OCR

同一张 1077 × 1700 的公共领域古籍扫描页在手机内依次运行：

1. 原图 OCR；
2. 自动对比度灰度 OCR；
3. Otsu 二值化 OCR。

真机耗时 511 ms。三路一致性排序选择 `original` 为主稿；二值化稿虽然检出字符更多，但与其余两路一致度较低，因此没有被噪声字符数量误导。每一栏同时保留其他预处理的空间重叠候选，供下一步看图复核。

### 02 Qwen Base + 古籍 LoRA 同图复核

代表栏输入：同一栏图片 + OCR 主候选 `始以十级為準擬高千尺後財力不敷止建七級`。

| 候选 | 真实后端 | LoRA 状态 | 耗时 | 输出 |
|---|---|---:|---:|---|
| Qwen3-VL-2B Base | MNN Android JNI | 未加载 | 4452 ms | `始以三級為准擬高千尺後財力不敷止建七級` |
| Guji LoRA | MNN Android JNI | `adapterLoaded=true` | 4492 ms | `始以十三為準擬高千尺後財力不敷止建七級` |

这组结果证明 LoRA 的领域价值与边界同时存在：它比 Base/OCR 更好地辨出了“十三”并保留繁体“準”，但仍漏掉一个“級”。因此产品不允许生成模型自动覆盖 OCR 主稿，必须通过双候选一致性或人工确认。

### 03 确认稿断句与释义

确认稿：`始以十三級為準擬高千尺後財力不敷止建七級`

Qwen3-VL-2B Base 通过 MNN 端侧文本链路运行，耗时 5194 ms，输出：

> 【断句稿】始以十三級為準，擬高千尺，後財力不敷，止建七級。  
> 【白话释义】开始按照十三级为标准来规划建造高度达到一千尺的工程，但后来财政力量不足，最终仅建成七级。  
> 【疑难提示】无

这一步只读取用户确认稿；提示词要求只加标点、不改原字，解释稿不会覆盖原始文字证据。

## 旅行 Skill：模型理解约束，工具执行事实

固定输入：京都 2 日，2026-08-15，美食 / 历史 / 小众，慢节奏，少走回头路，每天最多 3 个地点。

### Qwen Base

- `backend = mnn`
- `model = Qwen3-VL-2B / MNN native`
- 固定槽位提示实测耗时 1804 ms
- 输出：`目的地=日本;天数=2;兴趣=美食,历史,小众;节奏=慢;绕路限制=无;每日站数=3`

Base 能抽取多数软约束，但把“京都”泛化成“日本”且漏掉少绕路。因此目的地、日期、天数始终以界面输入为硬事实；模型无权改写。

### Travel LoRA

- `backend = mnn`
- `adapter = travel-planner`
- `adapterLoaded = true`
- 耗时 7015 ms
- 返回结构化旅行约束 JSON，包含日期、时长、美食 / 历史 / 小众等字段。

Travel LoRA 或 Base 只有真实 MNN 返回且通过输出门禁后，规划才继续；二者都失败时整次规划失败，不生成一份纯前端行程冒充 Qwen 成功。真实地点来自可替换城市数据 / OpenStreetMap，路线由确定性工具计算——这是 Agent 的职责分工，不是模型失败后的假结果。

## 决赛现场一句话

> 我们没有把小模型当万能 OCR 或万能行程生成器：算法负责可靠感知，Qwen / LoRA 负责语义校对与约束理解，确定性工具负责事实和路线，用户确认控制最终写入；每一步都能在 vivo 真机上展示真实 MNN 后端、耗时和 LoRA 加载状态。

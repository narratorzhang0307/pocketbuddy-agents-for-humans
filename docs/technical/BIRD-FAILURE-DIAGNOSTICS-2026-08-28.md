# 识鸟失败提示与长录音回归

日期：2026-08-28。范围是当前正式工作区的源码与本机测试；没有刷写硬件、构建发布包、安装手机 App 或上传音频。

## 本次修改

- 圆屏失败提示按实际阶段区分：蓝牙收音、音频校验、设备控制、本机语音指令、识别网络/服务、鸟图下载、图片回传及结果显示。短录音和无声保留专门提示，不再用“本次未完成，请重新录制”覆盖不同原因。
- 失败时通过已有 `avatar_skill_v1 = 0` 请求切回常驻 Frost，撤下此前的鸟图，无需网络下载。模式、头像和错误文字分别尽力发送；其中一条失败，不阻止后续错误文字发送，也不覆盖手机保留的原始收音错误。
- 新录音或断连仍取消旧操作；晚到的数据不能进入普通语音流程。上述行为是命令与生命周期测试，不是肉眼确认实板已显示。
- 在完整音频到达后，先完成设备控制，再标记识别请求已发出。控制命令失败不再显示“识别服务异常”或把 HTTP 标成“请求中”。

## 长录音缓存

本轮没有重复修改已有缓存实现：B 板初始化已预留 **960000 字节 PSRAM**，不是旧的 96 KiB。原有录音上限、20 秒尾包发送上限、手机 22 秒尾包等待与完整性拒绝规则保持不变。

新增回归覆盖：

- 10 秒、320000 字节输入，在录音期间以 0 / 8 / 16 / 32 KB/s 排出缓存；剩余尾包排出后逐字节一致，已用缓存清零。0 KB/s 案例仅证明暂时停发时缓存不溢出，不代表无线断开也能传完。
- 原生接收 1600 个音频分片，结束元数据先于音频到达时，必须收齐 320000 字节才算完成。
- 保留旧 96 KiB 缓存溢出复现、30 秒容量上限、环绕、半采样拒绝和 MTU 边界检查。

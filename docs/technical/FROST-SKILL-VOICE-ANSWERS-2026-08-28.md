# Frost 查询型 Skills：文字回答与吧唧语音

## 这次接入的链路

实体键录音 → BLE → iPhone 本机 ASR → 原有 `sendFrostAgentMessage` → 同一个 Frost 会话的 `frost.skill_answer` → 真实只读查询/本机摘要 → 阿里云 `qwen3.8-max` → MiniMax `speech-2.8-turbo` → 16 kHz 单声道 PCM → 原有 BLE 播放链。

打字和语音共用这个入口。查询不产生页面跳转计划；“打开练了吗 / 调用健身 Agent / 打开女性运动”继续走原来的页面与摄像头流程。没有重写 Frost、Taskmaster、阿里云或固件。

自动播放需要 App 在前台、吧唧已连接、自动语音处于开启状态。默认开启的偏好保留；断连/后台暂停，回来只处理新的按键录音，不补发旧录音。三种律动下载与同步保持删除。

## 费用、权限与数据

- ASR 仍在 iPhone 本机，录音不交给 Qwen 或 MiniMax。
- Qwen 收到当前提问、所需 Skill 规则、对应的工具结果/摘要，不发送完整聊天或健康导出。
- 每次问答最多一次实体抽取＋一次回答生成；睡眠/训练自述等不需要实体抽取的只有一次回答生成。网络失败不自动重试。
- MiniMax 只收到不超过100字的语音摘要。原训练提示音和其他系统朗读没有统一换成收费语音。
- MiniMax API Key 保留在服务器 `.env`。自动回答使用服务器签发的五分钟短票据，绑定本次语音正文。票据不能改写正文；同一票据复用成功音频或失败结果，不重复扣费。请求仍受现有服务端限流与每分钟6次合成限制。
- 现有演示站的 Frost 模型接口是公开且限流的；短票据不是账户登录。多人生产部署仍需在既有 API 前接入账户/设备鉴权和按用户预算，不能把这次改动当作多用户授权系统。
- 按住新录音、切后台、断连、关闭自动语音会取消待播放结果。已经发送到模型/语音提供商的请求可能已计费，不声称撤销账单，也不自动重试。

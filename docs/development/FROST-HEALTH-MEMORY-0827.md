## 执行链

确认餐食 / 真实训练完成 / 手机累计步数 → 本机 HealthEvent 事实库 → 本地日期汇总与用户确认的长期信息 → 同一个 Frost → 云端 Qwen 只读建议 → MiniMax 短回复 → 已连接硬件。

用户明确说“开始这个训练”后，Frost 才把当前未过期建议交给原有 Skill 页面。训练或操作真实完成后，再回写事实、更新汇总，供下一次决策使用。

关键入口：

- `FoodPhotosTab.tsx`：照片观察是候选，不证明用户吃过；必须明确确认、指定食用比例和实际时间，稳定 UUID 防重复。
- `frostHealthMemory.ts`：今日摘要、最近 28 天有记录日期的摘要、确认的长期目标/偏好/限制与有界来源清单；不附带原图或完整医疗对话。
- `frostConversation.ts`：手机文字和硬件转写共享运行时；查询不自动启动摄像头。建议与记忆 SHA-256 修订绑定，10 分钟过期；记忆变化、撤销授权或中间已有其他操作时不能执行旧建议。
- `server/health-memory.mjs`：服务端固定提示、字段白名单、限流和超时。建议模型使用 `QWEN_MODEL_HEALTH_MEMORY` 或现有旗舰配置；真实探针返回 `qwen3.8-max`。不自动重试可能计费的失败。
- `frostPhoneHealth.ts` / `FrostHealthPlugin.swift`：HealthKit 只读今日累计步数。首次由用户点击授权；曾成功读取后，在用户再次询问健康建议时尝试无提示刷新。拒绝/锁定/无数据保留未知或带时间戳的旧记录，不造出零步。
- `frostHealthBadge.ts`：另行授权后，只同步简短屏幕摘要；语音/录音优先，连接、授权、日期或记忆改变时撤销排队中的旧摘要。

## 事实边界

- 以本机时区的日历日归档，跨日撤回先作用于原事实再做汇总。
- 热量保留区间和覆盖情况，不声称是全天完整摄入，也不推导精确“剩余热量”。
- 累计手机步数替代而不是叠加跑步片段步数。
- 视频分析不计作用户训练；只有实际实时训练中观察到的活动时长和关联结果可以计入。
- 普通 Skill 查询仅记使用状态；查询食品并不等于吃过，打开训练页面并不等于完成训练。
- 撤回保留原事件和审计，不是物理删除。长期表单清空后保存可移除已保存字段。
- 原有长期聊天记忆不被清空；本实现不会把未经确认的医疗聊天推断写成个人诊断。
- 当前是单设备本机用户记忆，不承诺跨账号、跨设备云同步或加密备份。
- 硬件保留的是显示投影，不是健康事实库；屏幕 ACK 不代表语音播放完成或用户已听到。
